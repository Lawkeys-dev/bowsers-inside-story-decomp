# Decompiling

## Tools

- [objdiff](https://github.com/encounter/objdiff/releases/latest): download the GUI for your OS and set the project directory
  to the root of this repository. It reads `objdiff.json` (generated by `ninja`) and rebuilds files through `./dev.sh ninja`.
- [Ghidra](ghidra.md) for a first draft of each function.
- [decomp.me](https://decomp.me): the `decomp.me` button in objdiff creates a scratch (platform `nds_arm9`, compiler
  `mwcc_30_131`, flags preset from `tools/configure.py`) that can be shared to get help.

## Decompiling a function

Until source files are split along their original boundaries, each decompiled function gets its own file.

1. Pick a function in objdiff or in `build/usa/asm/` (run `./dev.sh ninja dis` to generate it). Leaf functions
   (no `bl` calls) and functions without globals are the easiest to start with.
2. Find its size in `config/usa/arm9/**/symbols.txt`:
   ```
   func_ov122_0206d978 kind:function(arm,size=0x34) addr:0x0206d978
   ```
3. Create `src/<module>/<function>.cpp`, e.g. `src/ov122/func_ov122_0206d978.cpp`. Until the owning class is known,
   declare the function `extern "C"` so that its symbol keeps the name from `symbols.txt`, and describe the data it uses
   with placeholder structs (`Unk_ov122_0206d978`) annotated with field offsets.
4. Declare the file in the module's `delinks.txt`, with the function's address range (`end = addr + size`):
   ```
   src/ov122/func_ov122_0206d978.cpp:
       complete
       .text       start:0x0206d978 end:0x0206d9ac
   ```
   Leave `complete` out while the code doesn't match yet: the original code is linked instead, so the ROM still builds.
5. Build and check:
   ```shell
   ./dev.sh ninja
   ```
   objdiff shows the match percentage live. `ninja` fails if a `complete` file doesn't produce byte-identical modules.
6. Once the file matches, run `./dev.sh ninja report` to update the progress report.

## Matching tips

- Variables declared in a different order, an intermediate variable or an `inline` helper change register allocation.
- Read the original assembly to recover the source structure: a `BOOL` flag set by a predicated `mov` often comes from
  `if (...) { flag = TRUE; }`, chained stores from `a = b = c;`.
- `tools/probe_compilers.py` compiles a file with every compiler version, useful if a function looks impossible to match.
- Functions using globals need their symbols: check the names in `symbols.txt` and declare them `extern`.
